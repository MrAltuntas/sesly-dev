# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

**Sesly** is an AI-powered voice cloning storytelling mobile application built with **React Native** and **TypeScript**. It features a hybrid voice creation system (Ready-made Google Voices vs. Instant Voice Cloning), real-time status updates, and a premium subscription model.

**Tech Stack:**
- Expo SDK 55 (React Native 0.83, New Architecture) with TypeScript (strict mode)
- Committed native projects: `android/` and `ios/` are hand-edited (e.g. the FCM channel in `MainApplication.kt`); never run `expo prebuild --clean` without re-applying them. `app.config.js` exports a plain object, so `app.json` is ignored by Expo config.
- React Navigation (native stack), MobX stores, Axios, Socket.IO
- Firebase Auth (Google Sign-In, Apple Sign-In via `expo-apple-authentication` + `expo-crypto` nonce) and Firebase Messaging (FCM push)
- `expo-audio` for both playback (single player, lock screen for the paid plans, Mini and Premium) and voice-sample recording
- `react-native-keyboard-controller` for every keyboard layout (`KeyboardProvider` in App.tsx)
- In-app purchases with `expo-iap` (Google Play Billing 9, StoreKit 2), validated by the backend; Firebase Crashlytics (`@react-native-firebase/crashlytics`, release builds only)
- Jest (`jest-expo`) unit tests under `src/**/*.test.ts(x)`

## Common Commands

```bash
npm install                 # Install dependencies (run `npx expo install --fix` after a fresh install)
npm start                   # Expo Metro bundler
npm run android             # expo run:android
npm run ios                 # expo run:ios (on a Mac; pod install first, signing in ios/Sesly.xcworkspace)
npx tsc --noEmit            # Type check (must be clean)
npm test                    # Jest
```

Release builds (minified, shrunk, no `console.log`): follow `docs/release-pass/RELEASE-CHECKLIST.md` (gradle clean first, keep `mapping.txt`, AAB for the store).

## Architecture

### React Native + TypeScript Structure

- **Services**: API & Logic (`src/services/`) - Singleton services for API calls (AuthService, VoiceProfileService, StoryService, NarrationService)
- **Models**: TypeScript interfaces with strict typing (`src/models/`) - All models have type-safe parsers
- **Screens**: UI Components (`src/screens/`) - React functional components with hooks
- **Navigation**: React Navigation (`src/navigation/`) - Native stack navigator
- **Theme**: Colors and styles (`src/theme/`)
- **Config**: Constants and environment config (`src/config/`)

### Design v4 "playful" (every screen re-skinned, 2026-10-15)

The approved design is `../design/v4/playful` (README with the palette tables and the type scale, `index.html` with every frame's markup, CSS and copy, sheets `<palette>-sheet.png`). Six frames exist (home, Keşfet, story detail, player, Sesim, onboarding step 2); every other screen is restyled in the same system. Traits: chunky rounded cards and buttons on a darker lip that sink onto it when pressed, one action colour, four category colours, rounded display headings and Nunito body, the parent's own voice as the hero.

- **Theme (dark only).** There is no light theme and no Sistem / Açık / Koyu setting. `src/theme/palettes.ts` is a registry of six palettes (`kitaplik`, `orman`, `gece-mavisi`, `murekkep`, `erik`, `orijinal`) with the tokens of the CSS `.theme-*` classes; `derivePalette` adds what the CSS derives with `color-mix()` (own-voice gradient `ownA/B/C`, chip tints `chipOk*` / `chipAct*`, category tiles `cat.<slot>`, `glass`, `scrim`). `error` is the only token the mockup does not define. `categoryColors(T, story.category)` maps BEDTIME / TURKISH_CLASSICS / WORLD_CLASSICS / EDUCATIONAL to the uyku / turk / dunya / egitici slots. The default is `gece-mavisi`. `ThemeProvider` holds the palette and stores a pick under `@sesly/palette`; it never touches the colour scheme (see System bars). **Read colours only through the hook, styles through `themedStyles`:**
  ```ts
  const makeStyles = (T: Theme) => StyleSheet.create({ ... });
  const stylesFor = themedStyles(makeStyles); // one sheet per palette, cached at module level
  const styles = stylesFor(useT());
  ```
  The factory reads only `T` (window sizes, insets and props go in inline styles). Never a module-level `StyleSheet` with colours, never a hex colour in a screen (tints through `withAlpha` / `mix` in `src/theme/color.ts`). Colour rules: `T.action` means "do it" (primary button, play, progress, selected filter, active tab), category colours only mean "what kind of story", fills carry dark text (`onAction`, `onCat`). Every navigator route sits in its own palette boundary, `withScreenPalette` (RootNavigator, `lazyScreen`, the tabs), so a pick recolours the focused screen at once and the hidden ones settle a moment later; `withThemedChrome` is gone.
- **Palette picker (permanent).** Users choose their palette: Profile shows "Renk paleti" (`components/profile/PalettePicker`, six named swatches); a pick recolours every screen, sheet and system bar at once and is kept on the device (`@sesly/palette`). Every screen must work in all six palettes: colours only through `useT()`, and `theme.test.tsx` checks every text level (text, text2, text3, action, the status colours) at 4.5:1 or more on bg, surface, surface2 and the bar of each palette (`orijinal` text3 is one step lighter than the mockup for that).
- **Type.** Baloo 2 600 for display and Nunito 700 / 800 (subpath imports such as `@expo-google-fonts/baloo-2/600SemiBold`, never the package roots, which would bundle every weight; registered in App.tsx under `FONTS`, one family name per file, never a `fontWeight` on them). The mockup's Fredoka has no ğ, ş, İ, Ğ, Ş (Android drew them in Roboto), so it was replaced; `src/theme/fonts.test.ts` reads the cmap of every registered file and fails on a missing Turkish letter. `useTextStyles()` / `makeTextStyles(T)`: `displayL` 32, `displayM` 28, `heading` 21, `subheading` 18, `tile` 15 (Baloo 2, one step above the mockup because of its smaller x-height), `body` 15.5, `bodySmall`, `label`, `labelLarge`, `meta`, `eyebrow`, `link` (Nunito). Every line height is at least 1.3 times the font size (Android clips accents below that; a test enforces it), and text containers never get a fixed height. No uppercase labels.
- **i18n.** `src/i18n` (i18next + react-i18next, device locale from expo-localization). Namespaced JSON under `src/i18n/tr` and `src/i18n/en`; both must have the same keys, and an English value may not be a copy of the Turkish one (a test enforces both, plus the glyph rules). `const { t } = useTranslation('home')`, other namespaces as `t('common:retry')`. No hard-coded UI strings. Stores, services and helpers use `msg('key')` from `src/i18n/messages.ts` (namespace `messages`), resolved when shown, never at module scope. Do not name an interpolation variable `count` (plural resolution needs Intl.PluralRules, which Hermes lacks). The UI language (Türkçe / English) is set on the profile screen and on the onboarding footer (before sign-in) through `setUiLanguage()`. The backend hears it for pushes and e-mails (`i18n/uiLanguageSync`, started by BootStore: once per account and language, at a session start and on every change, always its own `PATCH /users/me/preferences { uiLanguage }`, a failure ignored, since an older backend refuses the unknown field with 400). The password reset mail comes from the backend in it (`AuthService.sendPasswordResetEmail`: `POST /auth/password-reset { email, lang }`, not Firebase's one-language template; always the "if an account exists, we sent a link" toast, 429 shows `auth.tooManyAttempts`). A sentence the backend writes itself (slot limits) is shown only when it is in the UI language (`i18n/serverText`); otherwise the app's own copy.
- **Sizes and press rules.** One scale for everything (`src/theme/theme.ts`, SPEC-design 1): `SPACE` 2 / 4 / 6 / 8 / 12 / 16 / 20 / 24 / 32, `RADIUS` 6 / 12 / 16 / 20 / 24 / 28 / 32 / pill, lips `LIP` sm 2 / md 3 / lg 4 (`lipFor(faceHeight)`: up to 48dp sm, under 72dp md, else lg; cards, rows and fields use md; there is no 5dp lip). Buttons (`buttonMetrics.ts`) are sm 36 / md 44 / lg 52dp faces on 2 / 2 / 3dp lips; lg is only the one bottom call to action of a screen or form, everything in sheets and dialogs is md. Press rules: only a face with a visible lip sinks (by exactly its lip); a target without one dims (`usePressTint`); the sink waits `PRESS_DELAY_MS` (100 ms) so a swipe through a list never flickers, and controls outside scrolling content (transport, steppers, tabs, docks) pass `pressDelay={0}`; faces are opaque (a translucent face shows the lip through it). `SurfaceLevelProvider` marks which step of the neutral ladder a container is (sheets, dialog cards, cards, the mini player), so neutral controls inside draw one step up and never in the container's colour; providers sit only in containers, never in `Tactile`.
- **Components.** `src/components/design`: `Tactile` (the lip and the press sink: the face moves down by the lip on a native-driver transform; `usePressSink` for custom faces; the face is `${testID}-face`, the lip `${testID}-lip`), `Button` (primary, secondary, ghost, text; sm / md / lg as above), `IconButton` (plain 48dp target; tactile 44dp on a 2dp lip; glass over artwork; badge, a 28dp circle on a cover; `badgeCount` puts a count bubble in the corner, the queue length, and is the button's accessibility value unless `countInLabel` says the label already names it, as on both queue buttons; a count that goes away sets an empty value, since Android keeps the old one), `SearchField`, `ModalWindow` (the one `Modal` wrapper: transparent bars, its own gesture root), `DialogOutlet` / `withDialogOutlet`, `Chip` (`.fc`), `Tag` (`.chip`), `SegmentedControl`, `Switch`, `SwitchRow`, `Checkbox`, `Card`, `CategoryTile`, `CategoryDot`, `ListRow` (plain or `card`), `TopAppBar` (`scrolled` from `useScrollEdge()` draws a canvas fade under the bar once the list scrolls), `Avatar` (lip and corners from `avatarLip` / `avatarRadius`, so skeletons read the same values), `TextField`, `StateView`, `StateIcon`, `BottomSheet`, `Dialog` (behind `useDialog()`), `snackbar` + `SnackbarHost` (a `tone`: a check for success, an alert for errors and warnings), `PictureCover`, `CoverCard`, `CoverMeta`, `useCoverSpread`, `LanguageCodes`, `TranslationBadge`, `MiniPlayerBar`, `Waveform`, `ProgressBar`, `Spinner`, `CircleButton`, `SectionLabel`, `SectionHeader`, `Icon`. `Icon` is the only icon source: app icon names mapped to Ionicons glyphs (`@expo/vector-icons`, preloaded in App.tsx), outline by default and the filled twin with `filled` (the selected tab); 24 for navigation and actions (`ICON_SIZE`), 20 inline in rows and buttons (`ICON_SIZE_INLINE`), 16 for marks inside chips, checkboxes and badges. `back15` / `fwd15` are drawn by `SkipIcon` (its own arc in the Ionicons stroke style, the number clear of the chevron). `Spinner` is the platform `ActivityIndicator`. Feature components live next to their screens: `components/story`, `components/detail`, `components/library`, `components/voice`, `components/voiceflow`, `components/audio`, `components/profile`, `components/states`.
- **Loading.** Never a dark overlay, a dimmed list or a lone centred spinner for content. Lists, shelves, story detail, the Sesim cards and profile rows load as skeletons of their own shape (`components/design/Skeleton`: `SkeletonPulse` around `Bone` / `RowSkeleton` / `ShelfSkeleton` / `StoryGridSkeleton`, shapes on the same lips as the real cards, so nothing jumps); the first real content after a skeleton fades in once (`FadeIn`, skipped when it came from a cache); a list that refetches keeps its rows and shows a thin indeterminate `ProgressBar` in a slot that is always there (Keşfet). Only where no shape makes sense (a consent text, the player fetching a narration) a spinner with a short label (`LoadingLine`), with the way back on screen.
- **Sheets and dialogs.** `BottomSheet` and `Dialog` animate in and out (`usePresence`; `onOpened` / `onClosed`), a sheet drags down to close from its handle and header, and a sheet's body never changes height while it is open. iOS refuses a dialog presented from the root while a sheet or a `presentation: 'modal'` screen is up, so the one `useDialog()` dialog renders in the top dialog outlet: every visible sheet's window and the five screens of the voice flow's modal group (`withDialogOutlet` in RootNavigator) carry one; a `showDialog` while a sheet is leaving waits until it is gone (`sheetPresence`). Run the follow-up of a sheet action from the sheet's `onClosed`, never after a guessed delay.
- **Keyboard.** `react-native-keyboard-controller` only: `KeyboardProvider` (edge-to-edge kept) in App.tsx, its `KeyboardAvoidingView` inside `BottomSheet` and `Dialog` (a dialog with a field rises by half the keyboard), `KeyboardAwareScrollView` on the auth forms and the voice name step. No React Native `KeyboardAvoidingView`, no manual keyboard listeners. Enter moves to the next field and submits on the last one.
- **Messages.** `showToast.*` shows a snackbar at the bottom with its level as the tone (optional third argument `{ label, onPress }` for an action, which keeps it up for at least 6 s).
- **Covers.** `PictureCover` shows `coverImageUrl` or one of ten placeholders in a rounded card on its lip, with a 1dp `coverRing` and optional badges, 22dp pills 6dp in: the duration on a glass chip at the bottom left, the AI translation mark (`translation`, the sparkles of `TranslationBadge iconOnly glass`) on the same glass at the bottom right, the level badge at the top left, and `locked` (a premium story the plan does not play) as a lock on glass at the top right; the title is never drawn on the picture (`CoverCard` puts it under the cover). The Home shelves and the story page's related row use `components/story/ShelfCover` (100 x 146, duration, mark and lock all on the picture, nothing under the two title lines), so every shelf has the same fixed height (`shelfListHeight`) and nothing moves while Home loads; the Keşfet grid card (`StoryCard`) carries the duration and the mark on its cover too, and its meta row under the title is the category dot and the category name. The placeholder comes from a stable hash of the tale key; every shelf or list passes `placeholderIndex={useCoverSpread(stories).get(story.id)}` so neighbours never show the same picture.
- **Shell.** `MainScaffold`: a tab bar in the `bar` colour (the active tab is a 56 x 32 pill on a 2dp lip, fully inside the bar, with the filled icon in the action colour) with Masallar (`Stories`, Home), Keşfet (`Discover`, search, filters, sort; its bar is the tab title like Kütüphane and Sesim with a search icon that unfolds the field over the title, folded again only by its close tile or, while empty, the back button, and the filters button beside it), Kütüphane (`Library`: Masallarım and Kaydedilenler; another screen asks for a segment with `requestLibrarySegment('saved')`), Sesim (`Voices`). The mini player (`MiniPlayerDock` / `MiniPlayerBar`) shows only while a story plays, and for `DOCK_PAUSE_HOLD_MS` after a pause from its own button (`audio.showMiniPlayer`); it floats over the tab scene as an overlay above the bar, with the content fading out behind it, so showing or hiding it never changes the scene's height (tab lists leave room with `useMiniPlayerInset()`). A paused story is resumed from the Library: "Kaldığın yerden devam et" (`ContinueListeningCard`, decided once per focus by `useLastListened` from the record the audio store writes at every start, `utils/lastPlayed`, per account) sits at the top of Masallarım. Switching tabs is instant; a hidden tab is frozen. Profile (which holds every setting) is reached from the avatar.
- **Catalogue.** The content language ("Masal dili", `useContentLanguage().effective`) is the stored pick, else the UI language when it is a catalogue language with stories, else the catalogue default; the backend's `effectiveContentLanguage` is never used (it falls back to Turkish for a null pick). Before the account's pick arrives, the device copy stands in (`seed()`, local). Every change of it (a pick, or the UI language without one) refetches the lists (`StoryStore.contentLanguageChanged`, the Keşfet, collections and "Yeni eklenenler" reactions). Home lists one language: the hero, the newest stories and the category shelves are flat lists (`language: <code>`), the saved shelf keeps the tales saved in it, so no cover there names a language. Keşfet's Dil filter starts on the content language (`DiscoverStore.languagePicks` null; not counted, no chip, "clear" goes back to it), picks are flat lists, every language unpicked is the grouped whole catalogue (`grouped: true, prefer`); a search with no result in the default language offers "Tüm dillerde ara". A card or the hero names its language only when it is not the content language. The other versions of a tale stay on the story page (languages, "Başka dillerde"). "Masal dili" in Profile shows with two or more languages with stories. Saving is per tale (`isStorySaved`, grouped favourites). Translation requests: `StoryService.requestTranslation` / `cancelTranslationRequest`.
- **Story page extras (2026-10-21).** Content warnings (`models/contentWarnings`, the values of the backend enum `ContentWarning`: SCARY, VIOLENCE, DEATH, SAD_ENDING, BAD_EXAMPLE, OLD_LANGUAGE, LONELINESS, which are also the i18n keys `story:contentWarning.label.<VALUE>` / `.sentence.<VALUE>`; an unknown value, an old Turkish key such as `korkutucu` too, is ignored; `Story.contentWarnings`) are calm `Tag`s next to the age tag; `contentNoteText` ("3-6 yaş için. Korkutucu bir sahne içeriyor.") shows on the preparation screen and under the player title the first time a narration's player opens (`utils/contentNotice`, AsyncStorage, newest 300). The page opens on a hero (`components/detail/StoryHero`): the cover full-bleed from the very top of the screen (`storyHeroHeight`: 1.15 times the width tall, at most 56% of the window, plus the status bar; only the quiet bottom of the cover is cut), a canvas gradient over the bottom part of the band only (`HERO_SHADE_STOPS`: clear above 70% of the band, 92% from 87% where the title's last line sits, solid at the edge; the title takes up to two lines, shrinking a little before a third, with a soft canvas glow behind the letters; a test checks the title at 4.5:1 or more on any picture in all six palettes) and the Baloo 2 title on it (the screen's header). The top bar floats over it: glass back, save and more (`IconButton variant="glass"`), taking the canvas colour once the picture has scrolled under it. Below the narrators, after the push: credits, languages, then "İlgili masallar" (`components/detail/RelatedStories`: `GET /stories/:id/related` through `StoryService.getRelatedStories` / `parseRelatedStoriesFromJSON`, kept per session; three shelf covers with a caption line, the other language versions first, then the other parts ("Bölüm 2"), then more of the category; "Tümü" like the narrators' link opens `RelatedStoriesSheet` with every related story under "Başka dillerde", "Diğer bölümler", "Aynı türden masallar", empty groups left out; a tap pushes that story's page, a locked one shows the plans; bones while loading, the section hidden when nothing is related or the request fails), and always last "Kaynak ve lisans" folded into one row (`StorySourceSection`, title and chevron, expanded state for screen readers). A machine translation shows `MachineTranslationNote` under the summary ("Bu metin İngilizce aslından yapay zekâ ile çevrildi.", and "Orijinalini aç: <title> (<dil>)" when the backend's `translation.original` is published) and in lists and the narration confirmation the badge reads "Yapay zekâ ile çevrildi" with the sparkles icon (the story page has only the note). A human translation gets no badge; its translator is in the credit. "Kaynak ve lisans" (`storySourceRows`: source address, attribution, licence, licence address, then "Kapak resmi" from `credit.coverCredit`, the plain-text credit of a CC BY or public domain cover picture) is information only: selectable text, never a link that leaves the app. `Story.coverKey` (the backend's tale key) seeds the placeholder picture (`coverSeedKey`); the backend already lends a coverless story its tale's cover.
- **Removed audio.** A narration that exists but is not READY (an admin removed its audio) is `loadError: 'audioRemoved'` (`utils/loadErrors`): a fetched start, the background refresh and a failed stream (`explainStreamFailure` asks the status once) set it; the queue skips it and the continue card forgets it like `notFound` (`isUnplayableLoadError`); the player shows "Bu masalın sesi yenileniyor" with "Yeniden oluştur" (the story page), never a retry.
- **Narration confirmation.** Every NEW narration is confirmed in `components/detail/NarrationConfirmSheet` (words from `narrationConfirm.ts`): the story page's action, "Baştan hazırla" in its options, and "Yeniden hazırla" on the generation screen's already-narrated state. It shows the story (cover, title, `StoryDetail.part` as "Bölüm 2 / 3", language, length, age, content warnings, the AI-translation badge), the voice (name, "Hazır anlatıcı" / "Kendi sesin", its language, the `narrationLanguageNotice` line or the "Dil uyuşmuyor" warning) and the cost from GET /usage or the plan ("Bu seslendirme hazır anlatıcı hakkından 1 kullanır (bu ay 4/20)."; nothing for an unlimited bucket); a used-up allowance shows the block and "Planları gör" instead of "Seslendir". The choice runs once from the sheet's `onClosed`. Playing a ready narration, following one being prepared and a retry after a failed start never ask.
- **Player.** `AudioPlayerScreen` (`AudioPlayer: { narrationId, autoplay? }`) derives everything from the audio store and keeps no copy of the narration: it opens at once for the loaded story and for every narration whose meta is known (`stores/narrationMeta`), shows a loading line only for an unknown one (a push tap), and follows the store's queue with `setParams` (never a remount). The glass top bar has the queue button (`queueSheet.open('player')`), the transport has previous / next while the story plays from a queue of two or more, a stream that never sounded shows an inline retry, and a story that ended with nothing after it shows the end card ("Baştan dinle", and the next story when the queue or the home shelf has one). The artwork grows with the phone's height so tall phones get no empty band. Two option tiles: the sleep timer and the speed. Playback speed (0,5 to 2,0, `components/audio/SpeedSheet`) is applied with the expo-audio playback rate; "use for all stories" is stored in the preferences settings bag and mirrored on the device. The sleep timer (`SleepTimerService`, `TimerSheet`) has a story-count mode and a duration mode (wall-clock deadline) with a fade over the last minute; on Android the duration's fade and pause run natively next to the player (the deadline lives in `modules/sesly-media`, `utils/sleepDeadline`), so it stops on time with the screen off, and JS only mirrors the countdown.
- **Queue ("Sıradakiler").** Local and per account, not the backend playlist (`PlaylistStore` / `PlaylistService` are gone; named synced lists can come back on `/playlists` later): `stores/QueueStore` (unique by narration id, at most `QUEUE_MAX`, one AsyncStorage snapshot per user), `stores/queuePlayback` (`playQueueFrom`, `playNext`, `playPrevious`, `bindStoryEnd`), `stores/queueSheet` + `components/audio/QueueSheet` (mounted once by `QueueSheetHost`). Users add only narrations that exist: from the story page (a ready narration of the chosen narrator), a Library row's "Sıraya ekle" button beside play, and "Hepsini çal"; every add says so with "Sırayı aç". Story cards offer no queueing. Nothing in the app uses a long press: every action is a visible control (a Library row has "Sıraya ekle", play and "more").
- **Playback progress.** Never draw a progress bar from `audio.currentPositionMs` and never run a JS timer for it. The loaded narration has ONE native-driven `Animated.Value` (`utils/playbackProgress`, bound to the audio store); the player waveform, the mini player line and the library row all read it and move with transforms (`AnimatedFill`, `ProgressBar progress=`). For labels read the store's computed values (`positionSeconds`, `remainingMinutes`, `hasPosition`) so only a small observer re-renders. The real length the player reports is kept per narration in `utils/narrationDurations` and wins over the backend's `totalDuration` (which runs long): use `resolveNarrationDurationMs(id, estimate)` wherever a narration's length or time left is shown.
- **Voice languages.** Every voice has a language: `VoiceProfile.contentLanguage` ("tr", "en", the vocabulary of `story.language`; `resolveVoiceContentLanguage` reads a backend that does not send it as Turkish, or from the locale of a ready-made voice id). Every row that names a voice with detail shows it in its own name ("Türkçe, 12 Ekim kaydı", "English, kadın sesi": `voiceLanguageName`, `narratorLine`). Any voice may read any story; `narratorsForStory` lists the voices of the story's language first and the rest as `other` ("Başka dildeki sesler" in the narrator sheet), and `narrationLanguageNotice` says what a mismatch means: the user's own voice is warned about in the narration confirmation ("Dil uyuşmuyor", it will sound accented), a ready-made narrator gets one quiet line under the narrator row because the backend reads it with the same narrator's voice of the story's language. A narration response carries `voiceLanguage`, `storyLanguage`, `languageMismatch`, `nativeVoiceUsed`; `isNarrationAccented` puts "aksanlı" on the library row. There is no "voice cannot read this language" error any more.
- **Ready-made narrators.** Google Chirp 3 HD voices only, free for every plan: no premium flag, lock or quality tier. Shown by bare name (`bareVoiceName` / `getNarratorDisplay`). The catalogue is requested per content language (`voiceProfileStore.loadAvailableVoices(language)` / `catalogueFor(language)`): the story's language in the narrator sheet, the language of the filter chips on the Sesim tab (default "Masal dili"; an added narrator is listed under its own language). Adding one goes through `useAddNarrator`. The Sesim tab shows the first six rows of a language; "Tümünü gör" opens `NarratorCatalogue` (all narrators of one language, the same language filter, the catalogue order kept with added ones marked in place, virtualised), which is also where a story without a usable voice sends the user (`pickForStory`, back to the story after an add). A sample is watched by the audio store (`previewPending`, `previewFailed`): a screen that starts one resets its button on `previewFailed` and calls `acknowledgePreviewFailure()`.
- **System bars.** Native, not JS: Android is pinned to night mode before React Native loads (`AppCompatDelegate.MODE_NIGHT_YES` in `MainApplication.kt`, hand-written) and iOS by `UIUserInterfaceStyle Dark` in Info.plist; there is no `Appearance.setColorScheme` pin any more. The bars are edge to edge with light icons; the Android navigation bar is transparent with no contrast scrim from Android 10 (only Android 7 to 9 get the palette's bar colour from `ThemeProvider`). A `Modal` is its own Android window, so `ModalWindow` mounts the zero-size view of the local module `modules/sesly-system-bars` (`getModalSystemBars()`, null on iOS and in a build without it) to keep that window's navigation bar transparent too. `BottomSheet` mounts its own `SnackbarHost inSheet`, so a message shown while a sheet is open is visible.
- **Boot.** No JS splash and no Splash route: the native splash (expo-splash-screen, the bird mark on the dark launch colour) stays up until the navigator drew the first route (`src/boot/splash.ts`). `BootStore` (`src/boot`) reads one storage snapshot, applies the stored language and palette, starts the AuthStore from the cached user without waiting, and decides the first route from local data (`decideBootRoute`: the cached `/app/config`, the tokens, the cached user, the onboarding flag); only tokens without a cached user wait for the live session check, time-boxed. A returning user lands on Masallar even offline; force update runs in the background.
- **Plans and quota.** Mini is a paid plan: background playback, the lock screen, premium stories and unlimited ready-made narrators, like Premium; only the number of cloned narrations differs. Read the plan through `SubscriptionStore` getters, never a tier: `planId` (`GET /usage` when it answered, else the tier), `isPaid`, `canPlayInBackground`, `hasPremiumStories`, `isPremiumPlan` (no bigger plan to offer). `isPro` / `isFree` are gone. Allowances come from `GET /usage` (`models/Quota.ts`, `parseUsageSummary`); a refused narration or voice is a `QuotaBlock` (`parseQuotaBlock`, copy from `describeQuotaBlock`) with "Planları gör", never a generic failure. Voice dialogs take the `planId` (`describeSlotBlock`, `describeCloneError`).
- **Top bars.** The tab screens with the avatar use `components/common/TopBarAccount` (a tactile bell with an unread dot, then the avatar). The brand bar shows `SeslyMark` (density-matched `logo-mark.png` up to 32dp) before the wordmark.
- **Own voices as slots (Sesim).** Cloning costs money, so Sesim never promotes it: no hero card, no big "Yeni ses" button. "Kendi seslerin" shows the allowance card (`OwnVoiceLimitsCard`: "Ses yuvası 1/3", voices held of `cloneVoiceSlots`, and "Bu ay yeni ses hakkı 2/5", "Toplam" on the free plan, from GET /usage through `ownVoiceLimits`, falling back to the slots answer and `PLANS`), one compact `OwnVoiceSlot` per own voice (the plain row card of the narrator rows: surface face on the standard lip, no gradient, glow or coloured lip; only the mic glyph on its neutral tile is in the own colour), then one modest dashed `EmptyVoiceSlot`: "Ses ekle" (the normal add-voice flow) or why not (`newVoiceBlock`: cloning closed, slots full, the period's new voices used up) with "Planları gör" while a bigger plan helps. A delete frees a slot but never gives a creation back, and the delete dialog says so (`cloneDeleteMessage`). No purchase of extra slots is offered.
- **Backend placeholders** (marked `BACKEND PLACEHOLDER`): friendly narrator names and descriptions (`models/Narrator.ts`), the tale key (`Story.translationGroupId`), the listened state of a narration (`components/library/narrationProgress.ts`). Plan names and reference prices are the typed `PLANS` (`models/Plans.ts`); usage is live from `GET /usage`. Synced text has no client code until the backend sends sentence timings.
- **In-app purchases (2026-10-22).** `expo-iap` 6.1.1 (an Expo module, autolinked; Android pins `openiapStore=play` in `android/gradle.properties`), loaded lazily through `services/iap/storeBilling` so a build or platform without it shows "Satın alma şu an kullanılamıyor" instead of crashing. Product ids live in `PLANS.productIds` and `services/iap/storeProducts` (Google `mini_monthly`, `pro_monthly`, `pro_yearly`; Apple the same with `io.sesly.`; the backend STORE_PRODUCTS). `stores/PurchaseStore` (started and stopped with the signed-in user by `usePurchaseBridge` in RootNavigator): connects, loads the products (the Android base plan offer: one pricing phase), buys with `obfuscatedAccountId` / `appAccountToken` = the Sesly user id, hands every purchase to the backend (`services/iap/validatePurchase`: POST /subscriptions/google/validate or /apple/validate) and finishes the store transaction only after a 200 or a receipt verdict (4xx); a 503, no connection, 5xx, 401, 408 or 429 keeps it (`keptCount`) and sends it again on the next start (Android lists unacknowledged purchases of this account; iOS replays unfinished transactions to the listener) and on every return to the foreground. A Google pending purchase is never validated or finished until paid. `flow`: purchasing, verifying, pending, deferred (paid, not verified yet), success. An Android plan change replaces the old purchase token (`with-time-proration` up, `deferred` down). `restore()` re-sends the store account's active subscriptions; `manageSubscriptions()` opens `GET /subscriptions/current.managementUrl`, else the store's page. `SubscriptionStore` keeps `source`, `storeProductId`, `managementUrl`, `hasStoreSubscription` from GET /subscriptions/current. The plans screen shows the store's localised prices (the TRY reference prices of `PLANS` stand in only for a Turkish UI or a TRY storefront, `showsReferencePrices`; anyone else sees "..." until the store answers, "-" when it cannot), one notice (`purchaseNotice`), "Satın alımları geri yükle" while connected, "Aboneliği yönet" for a store subscription, and a calm success state. Play Console / App Store Connect setup: the backend's owner checklist and `docs/release-pass/RELEASE-CHECKLIST.md`.
- **Crash reporting.** `services/crashReporting` (called first in index.ts): Crashlytics collection only when `__DEV__` is false (firebase.json also keeps debug builds out), the library's global JS error handler, Hermes' unhandled-rejection tracker in release builds, the Sesly user id only (`onSessionUserChange`), and `recordNonFatal(error, 'narration' | 'purchase' | 'app', context)` with a short breadcrumb that drops personal keys (email, name, token, receipt...). Failed narration starts (not offline) and backend FAILED jobs, rejected or oddly failing purchases are reported. Development builds only: seven quick taps on the profile's version line crash the app and the next start sends that report. Android: `firebase-crashlytics-gradle` 3.0.3 with the R8 mapping upload of release builds (hand edits in both build.gradle files).

### Key Flows

1. **Voice Creation (Hybrid)**:
   - **Ready-made**: User selects a high-quality Google TTS voice (Neural2/Chirp).
   - **Cloning**: CreateVoiceProfile (name, and the voice language when the config's `supportedLanguages` offers more than one) -> VoiceConsent (consent text from `GET /voice-profiles/clone-config?language=`) -> VoiceRecording (15 s min / 30 s target / 60 s max, served by the config) -> create with the config's `locale` as `language`, upload with `consentVersion` + `speechStartMs`. The language is chosen only on the first step and travels as the `language` route param; the later steps read the config through `voiceProfileStore.cloneConfigFor(language)`, so the script, the consent and its version always belong to the language of the voice. `loadCloneConfig(language)` asks for Turkish without a parameter and falls back to it on a 400.
   - **Status**: one tracker in `useVoiceProfile` (socket `voice_status` + a single 5 s status poll).

2. **Story Narration**:
   - User selects Story + Voice Profile.
   - Backend generates audio chunks asynchronously.
   - `NarrationService` tracks progress via WebSocket events (`narration_status`).

3. **Audio Playback**:
   - **Library**: `expo-audio` is the **primary and only** audio player (one native player for the app's life, one source at a time: a story or a sample). `useAudioPlayer` returns the store; the app-wide wiring lives once in `components/audio/AudioSessionBridge` (mounted by `RootHosts`).
   - **One load path**: `startNarration({ narration } | { narrationId, meta }, { autoplay, fromQueue })` pauses the outgoing story and saves its position first, changes state only after the steps that can throw, and starts from a cached meta without a round trip. `isPlaying` is the user's intent; `isBuffering` / `isBusy` say the player still waits. A failed start keeps the previous story loaded, so `loadError` is named after its narration (`loadErrorNarrationId`): never blame the loaded story for a failure without checking it.
   - **End and autoplay are store-driven**: the end of a story is handled inside the status event by the handler `bindStoryEnd` installs (`stores/queuePlayback`): a used-up stories-mode timer stops there, a story started from the queue starts the next entry, anything else rests at its end. It works with the player closed and the screen off and uses no JS timer. There is no `didJustFinish` flag for a screen to consume.
   - **Playback**: Streams merged narrations from the `/narrations/:id/stream` backend endpoint (Google Cloud Storage origin), with a fresh token per start and a reload after 50 minutes.
   - **Plan gating**: Background playback + lock-screen controls belong to the paid plans, Mini and Premium (`SubscriptionStore.canPlayInBackground`). On the free plan a playing story pauses when the app goes to the background (the session bridge; a snackbar with "Devam et" on return). The audio mode (`shouldPlayInBackground`, `interruptionMode: 'doNotMix'`) follows the plan. Lock screen: on Android the local Media3 module `modules/sesly-media` (commands through `src/utils/mediaSession.ts`), on iOS expo-audio's `setActiveForLockScreen` / `updateLockScreenMetadata`; metadata updates are throttled (`src/utils/lockScreen.ts`), deactivated for the free plan, samples and stop.
   - **Sign-out**: session end handlers (`stores/session.ts`) unload the player (positions kept), turn the timer off, forget the queue in memory and empty the story, voice and other per-account stores before the user is cleared.

4. **Push Notifications** (FCM via `@react-native-firebase/messaging`, no expo-notifications/notifee):
   - `src/services/PushNotificationService.ts`: token register/unregister (`POST /notifications/register|unregister`), permission, FCM listeners. Registration follows the backend session. Sign-out does not wait on the network: it reads the JWT first, clears the session at once, and sends the unregister (and the backend revoke) in the background with the captured credentials through `ApiClient.postDetached`; a new registration waits for that unregister.
   - Permission is asked in context via `ensurePushPermission()` (first story generation / voice clone), never at launch, never re-asked after a denial (Settings offers the system settings page).
   - Foreground messages and taps are bridged in `src/hooks/usePushNotifications.ts`; tap routing uses `getNotificationTarget` + `src/navigation/pushRouting.ts` (queued until the Main shell is mounted).
   - Android channel `sesly-default` is created natively in `MainApplication.kt` (hand-written; `expo prebuild --clean` would drop it).

## Technical Details

### Build System & Configuration
- **Package Name**: `com.sesly` (Android & iOS)
- **MainActivity**: Located at `android/app/src/main/java/com/sesly/MainActivity.kt`
- **Gradle**: `namespace` and `applicationId` in `build.gradle` must match `com.sesly`
- **TypeScript**: Strict mode enabled, all code must pass type-check

### Libraries
- **Navigation**: `@react-navigation/native` + `@react-navigation/native-stack`
- **Network**: `axios` (HTTP), `socket.io-client` (WebSockets)
- **Audio**: `expo-audio` (Playback + Recording)
- **Storage**: `react-native-encrypted-storage` (Tokens), `@react-native-async-storage/async-storage` (Settings)
- **Auth**: `@react-native-firebase/auth`, `@react-native-google-signin/google-signin`, `expo-apple-authentication`
- **Purchases**: `expo-iap` (no react-native-iap, no RevenueCat)
- **Crash reporting**: `@react-native-firebase/crashlytics` (same version as the other @react-native-firebase packages)

### Real-time Updates
- **WebSocket**: App connects to Backend Gateway (`/notifications` namespace).
- **Events**:
  - `voice_status`: Updates UI when cloning finishes.
  - `narration_status`: Updates progress bar during story generation.

## Troubleshooting

### TypeScript Errors
- **Fix**: Run `npx tsc --noEmit` to see all errors
- All models have strict type checking - use the provided parse functions
- Never use `any` type - use `unknown` and validate

### "Unable to resolve module"
- **Fix**: Run `npm start -- --clear` (also once after any change to `babel.config.js` or `babel/strip-console.js`)
- There are no path aliases: imports are relative, and `babel.config.js` only adds the release console stripping

### Build Errors
- **Android**: Run `cd android && ./gradlew clean && cd ..` then rebuild
- **iOS**: Run `cd ios && pod deintegrate && pod install && cd ..` then rebuild
- Check that all native dependencies are properly linked via autolinking
