# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Sesly is a production NestJS backend API for an AI-powered voice cloning mobile app (Expo / React Native) that generates bedtime stories narrated in the user's chosen voice. Uses Google Cloud Native architecture (GCS, Google Cloud TTS) for ready-made voices, with Cartesia Sonic 3.6 (API version 2026-08-14) as the cloning + cloned-voice synthesis provider. Voice clone flow: KVKK consent (`GET /voice-profiles/clone-config`) -> upload (WAV transcode, lead-in trim, 60 s cap, no filters) -> `voice-training` Bull queue (3 attempts) -> `voice-maintenance` repeatable sweeper. Paid plans are sold only as in-app subscriptions (App Store, Google Play; Stripe was removed 2026-10-16), and real-time status updates go over WebSockets (Socket.io).

## Architecture

### NestJS Module Structure

Feature-based modules under `src/modules/`. Two separate auth systems:
- **User auth** (`auth/`): Firebase token exchange + JWT for mobile users
- **Admin auth** (`admin-auth/`): Email/password + JWT for admin panel

Key domain flow: **Narrations** orchestrate story + voice profile selection and delegate to **Audio** module for TTS generation. Audio module uses Bull queue (`audio-generation`) to process segments asynchronously via `AudioGenerationProcessor`.

Bull queues: `audio-generation` (jobs `generate-segment` and `prepare-audio`), `voice-training`, `voice-maintenance`, `story-llm` (machine translation, language-level and age-group tagging of stories, see "Story LLM tasks").

### Global Providers (registered in AppModule)

- `JwtAuthGuard` — all endpoints require JWT by default; use `@Public()` decorator to opt out
- `LoggingInterceptor` — request/response logging
- `HttpExceptionFilter` — the single global catch-all (set in `main.ts`): i18n-aware error envelope, and maps unhandled Prisma errors via `mapPrismaError` (P2002 -> 409, P2025 -> 404, P2003 -> 400). `PrismaExceptionFilter` is not registered globally (two catch-alls = only one ever runs).

### Path Aliases (tsconfig.json)

```
@/*        → src/*
@common/*  → src/common/*
@modules/* → src/modules/*
@config/*  → src/config/*
@prisma/*  → src/prisma/*
```

### Shared Utilities (`src/common/`)

- **Decorators**: `@Public()`, `@CurrentUser()`, `@CurrentAdmin()`, `@Roles()`, `@AdminRoles()`, `@ApiPagination()`
- **Guards**: `JwtAuthGuard`, `JwtRefreshGuard`, `AdminJwtAuthGuard`, `AdminJwtRefreshGuard`, `RolesGuard`, `AdminRolesGuard`
- **Pagination**: `PaginationDto`, `PaginationHelper`, `PaginatedResult<T>` interface — used across all list endpoints

### TTS Provider System

`TTSProviderFactory` resolves provider by voice profile's `provider` field (enum: `GOOGLE`, `CARTESIA`). Both implement `TTSProviderInterface`; Cartesia additionally implements `VoiceCloningCapableProvider` (createVoiceClone / deleteVoiceClone). Default provider is the `tts.defaultProvider` runtime setting (fallback: `TTS_PROVIDER` env var).

### Async Audio Pipeline

1. `NarrationsService.create()` or `AudioService.generate()` creates Audio + AudioSegment records
2. Each segment is enqueued as a Bull job (`generate-segment`) in `audio-generation` queue
3. `AudioGenerationProcessor` calls TTS provider, uploads to GCS, updates segment status
4. When all segments complete, audio is merged via ffmpeg and final URL stored
5. WebSocket event (`narration_status` / `voice_status`) pushed to client via `NotificationsGateway` on `/notifications` namespace

### Database

PostgreSQL with Prisma ORM. Schema at `prisma/schema.prisma`. Models use `@@map()` for snake_case table names. All IDs are UUIDs. Key relationships:
- `User` → `VoiceProfile[]` → `Audio[]` → `AudioSegment[]`
- `Story` → `StoryChunk[]` (text chunking for TTS)
- `StoryNarration` bridges Story + VoiceProfile + Audio (unique per user/story/voice)
- `Subscription` is one row per user: the store-backed entitlement plus the admin grant (see "Plans, limits and in-app purchases"); `StorePurchase` holds each store subscription, `StoreEvent` the audit / idempotency log

### Real-time Communication

- **WebSocket**: Socket.io gateway at `/notifications` namespace, JWT-authenticated via handshake token
- **FCM**: Firebase push notifications as fallback for background updates

### Configuration

Config files in `src/config/` use NestJS `registerAs()` pattern. All loaded globally in `AppModule`. Key configs: `app`, `database`, `redis`, `jwt`, `google`, `firebase`, `cartesia`, `gemini`. Config files hold connection data only (keys, hosts, API versions); tuning values are runtime settings (next section).

### Runtime Settings (admin panel, no redeploy)

Tuning values live in a typed registry, `src/modules/settings/settings.registry.ts` (key, group, type, range/options, env fallback, code default, Turkish label/description/unit). `SettingsService` (global `SettingsModule`) resolves each one as **panel override (table `system_settings`) -> environment variable -> code default**. `get(key)` is synchronous and typed; it reads an in-memory copy loaded at boot, refreshed every 30 s and right after a write. A database outage never fails the boot: env/default values (or the last loaded overrides) are served and a warning is logged.

- Registered: `rateLimit.ttl|limit`, `i18n.defaultLocale|fallbackLocale`, `content.enabledLanguages|defaultLanguage`, `llm.gemini.model|temperature|thinkingBudget|timeoutMs`, `llm.autoAssessLevel`, `llm.autoAssessAgeGroup`, `tts.defaultProvider`, `tts.google.speakingRate|pitch`, `tts.cloneLanguages`, `tts.cartesia.model|defaultSpeed|defaultVolume|defaultEmotion`, `tts.groupSegments`, `tts.sharePresetAudio`.
- **Read at call time** through `settings.get('...')`. Never copy a setting into a field in a constructor or at module scope, or panel changes stop applying.
- **Never register** API keys, secrets, URLs, `CARTESIA_VERSION`, database/Redis/JWT/CORS/storage config. A compromised admin account must not be able to read a secret or redirect a keyed request.
- Adding a setting: add the definition + its `SettingValueMap` entry, read it in the consumer, document the env fallback in `.env.example`. No migration needed.
- **Option labels.** An enum or list setting names its options in Turkish through `optionLabels` in the registry (content languages, locales, TTS providers, the Cartesia emotions via `SONIC3_EMOTION_LABELS_TR`). `GET /admin/settings` returns them as `constraints.optionLabels: [{ value, label }]` next to the raw `constraints.options`; values written through PATCH stay the raw ones. A new option without a label is shown as its value.
- Admin API (`admin-ops.controller.ts`): `GET /admin/settings` (SUPER_ADMIN, ADMIN), `PATCH /admin/settings` and `DELETE /admin/settings/:key` (SUPER_ADMIN only, audit line `AUDIT setting changed ...` in the log), `GET /admin/settings/options/gemini-models` (live model list, cached 10 min, always 200).
- Rate limit: `ThrottlerModule` resolves ttl/limit per request from the settings. The legacy `THROTTLE_TTL` / `THROTTLE_LIMIT` variables are ignored on purpose (they were never read; a stale `THROTTLE_LIMIT=10` would break mobile polling). Env fallbacks are `RATE_LIMIT_TTL_SECONDS` / `RATE_LIMIT_MAX_REQUESTS`.
- i18n: `HttpExceptionFilter` uses `i18n.defaultLocale` when the request has no `Accept-Language` and `i18n.fallbackLocale` for an unsupported language; `I18nSettingsSync` keeps nestjs-i18n's `fallbackLanguage` equal to the setting.
- Preset (Google) voice preview cache keys include a version segment and a hash of the Google prosody settings, so previews re-render when rate or pitch change (see "Ready-made voices").
- In unit tests use `createSettingsStub()` from `src/test-utils/settings-stub.ts`.

### Story Catalogue (multi-language, attribution, language level)

- **One `Story` row per language.** Translations of the same tale share a nullable `translationGroupId` (unique together with `language`: at most one story per language in a group). There is no translations table. `translatedFromId` records which story a translation was made from.
- **Content language is not UI language.** Clients pass an explicit `?language=` (never `Accept-Language`). `CONTENT_LANGUAGES` in `src/common/constants/content-languages.ts` is the list (tr, en, de, fr, es, it, nl, pt, ar, ru, with native name, English name and words per minute). The settings `content.enabledLanguages` / `content.defaultLanguage` decide what is served; always read them through `resolveContentLanguages()` / `resolveRequestedLanguage()` in `src/modules/stories/content-language.ts` (they keep the pair consistent). A request without `language` gets the default language, so app versions in the field keep seeing Turkish. A language that is switched off returns an empty list (collections: 404).
- **Status.** `StoryStatus` DRAFT / PUBLISHED / ARCHIVED. Every public list, search, language count and collection only returns PUBLISHED. `GET /stories/:id` (and narration create, favourite add) also resolves ARCHIVED, because old favourites and narrations point at them, but never DRAFT. An admin-created story is a DRAFT unless `status` is sent.
- **Publish rule** (`story-publish.rules.ts`): PUBLISHED needs `origin` and `textFidelity`; origins PUBLIC_DOMAIN, FOLK_ANONYMOUS and LICENSED also need `rightsBasis`, a source (`sourceName` or `sourceUrl`) and a credit (`authorName` or `collectorName`; a folk tale needs no name); `rightsBasis` CC_BY (any origin) also needs `attribution` and `licenseName` (missing keys `ccAttribution`, `ccLicense`; meta `publishRules.ccByRequires`). Single save, bulk publish and `seed:stories --publish` share it. Violations are a coded 400 `STORY_PUBLISH_REQUIREMENTS` with a Turkish message and `missing: string[]`. The rule is checked against the row as it will be after the write.
- **What clients see.** `story-list.mapper.ts` builds every client story field by field: `language`, `languageLevel` (CEFR A1..C2 or null), `summary` (editor text, else the first 150 characters; `description` carries the same text for old apps) and `credit` (public credit columns plus `origin`, `textFidelity`, `translationMethod`, and the licence credit a CC BY text needs: `attribution`, `licenseName`, `licenseUrl`; plus `coverCredit`, the plain-text line of the cover picture credit, see "Covers"), plus `isMachineTranslation` (translationMethod MACHINE) and `contentWarnings` (Prisma enum `ContentWarning`: SCARY, VIOLENCE, DEATH, SAD_ENDING, BAD_EXAMPLE, OLD_LANGUAGE, LONELINESS, mirrored in `prisma.enums.ts`, Turkish labels and `normalizeContentWarnings` in `src/common/constants/content-warnings.ts`; known values only, enum order; column `Story.contentWarnings ContentWarning[]`, migrations `20261021200000_story_content_warnings` (text column) and `20261022120000_story_content_warning_enum` (converts the old Turkish keys korkutucu, siddet, olum, uzucu-son, kotu-ornek, eski-dil, yalniz-ayrilik to the enum and stops with an error on any other stored value; the pre-deploy check query is in the migration, `test/content-warning-migration.e2e-spec.ts` covers it); admin create / PATCH and the import take an array or a comma separated string, trimmed and upper-cased, each value `IsEnum`; an old Turkish key is refused; `GET /admin/stories/meta` lists them as `enums.contentWarning`; a machine translation copies them) on every item. `GET /stories/:id` adds `translation: { isMachineTranslation, method, fromLanguage, original: { id, title, language } | null } | null` (`story-translation-source.ts`: the source is `translatedFromId`, a machine translation without one falls back to the group member in `originalLanguage`; `original` only when that story is PUBLISHED and in the same translation group). The rights-audit columns (`sourceRetrievedAt`, `rightsBasis`, `rightsNote`, `rightsVerifiedAt`, `rightsVerifiedBy`) and workflow columns (`status`, `slug`, `translationGroupId`, `languageLevelSource`, `languageLevelNote`, ...) are never serialised to the mobile API. A new column stays private until it is added to the mapper.
- **Language level.** `languageLevel` + `languageLevelSource` (AI | MANUAL) + note + assessed-at. A level sent to the admin create endpoint, or a level that differs from the stored one on PATCH, is a MANUAL assessment made now. A PATCH that re-sends the stored level (the panel saves the whole form) leaves source and assessed-at alone, so an AI assessment survives unrelated edits. The source is never accepted from a request body; the AI tagging job writes it directly.
- **Translation groups on PATCH.** `translatedFromId` only touches the group when its value changes; re-sending the stored value is a no-op. A story that already has a group never leaves it through this field: an ungrouped source is pulled into the story's group, a source in another group merges both groups (`mergeTranslationGroups`, shared with link-translation; 400 `TRANSLATION_LANGUAGE_TAKEN` on a language overlap). The unlink endpoint keeps `translatedFromId` (provenance) and only clears the group.
- **Slug.** Nullable, unique per language, generated from the title when absent (`slugify` in `src/common/utils/slug.ts` is Turkish-aware; `-2`, `-3` on a clash). A collection slug is also unique per language (`Collection.language`, default tr); a collection only holds, counts and lists published stories of its own language.
- **Search is Turkish-aware** (`src/common/utils/search-fold.ts`). `GET /stories/search` and the `search` of `GET /narrations` fold both sides with the SQL function `sesly_search_fold()` (NFD, accents stripped, ı and I to i, lower case), so "yildiz", "YILDIZ" and "Yıldız" are equal; never go back to `contains` + `mode: 'insensitive'` (ILIKE folds none of ı/İ/ş/ğ/ü/ö/ç). `stories."searchText"` is a generated column (folded title + content, `@ignore` in the schema with the introspected `dbgenerated()` default so `migrate dev` sees no drift). A raw query returns the matching ids, which the Prisma query intersects with its scope, so filters and pagination stay in Prisma. The term is always a bound parameter and LIKE wildcards are escaped. `npm run test:e2e` (test/search-fold.e2e-spec.ts) checks it against a local Postgres inside a rolled-back transaction. Admin and collection searches still use ILIKE.
- **Query helpers** for both the public and the admin list live in `story-query.util.ts` (`storyOrderBy`, level and language parsing). Sort keys: newest, oldest, title, duration, level; absent keeps newest first.
- **Admin** (`admin-content.controller.ts`): `GET /admin/stories` filters (language, status, languageLevel, category, ageGroup, origin, q, missingLanguage, imported, importBatch, reviewed, createdFrom, createdTo (YYYY-MM-DD, last day included), sort; `buildAdminWhere` is public and shared with the review list), `GET /admin/stories/meta` (languages + every enum with Turkish labels from `src/common/constants/story-labels.ts`; the panel keeps no hardcoded copy), `POST /admin/stories/:id/link-translation`, `DELETE /admin/stories/:id/translation-link`.
- **Duration.** `estimateDurationMinutes(content, language)` uses the per-language words-per-minute table, not a single Turkish figure. It is recomputed whenever the text or the language changes; the admin panel no longer sends `estimatedDuration` (the DTO field still exists as an override).
- **Seeding.** The old AI-written seed batches (`prisma/seed-data`, `runStorySeed`, `POST /admin/ops/system/seed-stories`) are gone: a fresh database gets no stories from code. A development database is filled from an import file through the import service: `npm run seed:stories -- --file <import json> [--dry-run] [--publish] [--batch <label>] [--allow-remote]` (`prisma/seed-stories.ts`, logic in `src/modules/admin/services/story-import-seed.ts`; ts-node with tsconfig-paths). DRAFT stories, no LLM or TTS call, idempotent; `--publish` publishes the created stories that pass the publish rule; a non-local `DATABASE_URL` is refused without `--allow-remote`. `npm run prisma:seed` (admin, test user) adds no stories; legal documents seed on boot.
- Adding a story enum: Prisma enum, the mirror in `prisma.enums.ts`, and the label map in `story-labels.ts` (typed by the enum, so a missing label does not compile).
- `splitStoryIntoChunks()` (`src/common/utils/story-chunks.ts`) builds the `StoryChunk` rows for both the admin editor and the translation job.

### One story per list (grouped catalogue, content language, translation requests)

A "tale" is every published story that shares a `translationGroupId`; a story without a group is a tale of its own. The helpers live in `src/modules/stories/story-groups.ts` and are shared by the catalogue, favourites, the library, playlists and collections.

- **Three list modes** of `GET /stories` and `GET /stories/search` (`StoriesService.resolveScope`):
  - neither `grouped` nor `language`: the default content language only, exactly as before. App builds in the field send nothing new and must keep getting this. Do not change it.
  - `language=tr` or `language=tr,en` (comma separated or repeated): flat, one row per story per selected language. A language wins over `grouped`.
  - `grouped=true` and no language: one item per tale. The version is chosen by `pickGroupVersion`: preferred content language, else the original-language version (`originalLanguage === language`, or no `originalLanguage` and no `translatedFromId`), else the default content language, else catalogue order (oldest, then id). Filters, sort, the plan rule and the search text apply to the chosen version; pagination and totals count tales. Implementation: one light query reads id/language/group of every published story in the enabled languages, the choice is made in memory, the page query filters by `id IN (chosen)`. Fine for a catalogue of thousands; revisit (SQL window function) before tens of thousands.
- **Preferred language** of a grouped list: `prefer=<code>` when sent and enabled, else the stored `UserPreferences.contentLanguage` when enabled, else `content.defaultLanguage`.
- **`availableLanguages`** on every story item everywhere (lists, search, detail, favourites, `narration.story`, collection stories) and at item level on playlist items (`language`, `availableLanguages`): the item's own language first, then the other published versions of the tale in enabled languages, catalogue order. Never empty for a story. `loadStoryGroupInfo()` reads it with one query per page.
- **`isFavorite` stays per row** (the favourite table points at one story). `isFavoriteAnyLanguage` is true when the row or any other language version of the tale is a favourite. `GET /stories/favorites?grouped=true` returns a tale saved in several languages once (preferred language when saved, else the most recently saved) with `favoriteStoryIds` and `favoriteLanguages`.
- **Content language preference:** explicit column `UserPreferences.contentLanguage` (null = use the default). `PATCH /users/me/preferences` validates it against the enabled languages (400 `CONTENT_LANGUAGE_NOT_ENABLED`); the response also carries `effectiveContentLanguage`.
- **Translation requests** (`src/modules/translation-requests`, table `story_translation_requests`). A request is stored on the story it was made from and counts for that story's tale; the group is resolved through the story at read time, so merging or unlinking groups never orphans a request. One open request per user, tale and language is enforced in the service (the DB unique is user + story + language). `POST /stories/:id/translation-requests { language }` (30 per hour per user, idempotent, 409 `TRANSLATION_ALREADY_AVAILABLE` when a published version exists), `DELETE /stories/:id/translation-requests/:language`, `requestedLanguages` on the story detail. Admin: `GET /admin/stories/translation-requests` (aggregated by tale and language, sorted by count), `translationRequests: { total, languages }` on admin story rows.
- **Fulfilment.** `TranslationRequestsService.fulfilForStory(storyId)` is called (with `void`, never throws) by `AdminStoriesService` when a story is created as PUBLISHED, becomes PUBLISHED, changes language or group while published, and for both stories of a link. Open requests for that language on the tale get `fulfilledAt` / `fulfilledStoryId` (rows are kept for statistics) and each requester gets one `TRANSLATION_READY` notification (in-app row + socket + push, not gated by a toggle) through `NotificationsService.sendNotification`. The seeder does not call it.

### Story LLM tasks (machine translation, language level, per-language segmentation)

All three use Gemini through `LlmPreprocessingService` (`src/modules/llm-preprocessing`); the prompts and response schemas live in `story-llm.prompts.ts`, the output checks in `translation-guards.ts`.

- **Segmentation is per language.** `preprocessStory(content, language)`: Turkish and English prompts are written out, the other `CONTENT_LANGUAGES` get `genericSegmentationPrompt()`. The Turkish prompt is byte-identical to the measured one (a spec pins its hash): do not reword it. The zero-drift guard is language independent.
- **Age group.** `assessAgeGroup(content, language)` returns `{ ageGroup, confidence, note }`: the age band (ZERO_TO_THREE, THREE_TO_SIX, SIX_TO_TEN, TEN_PLUS) the text suits as a bedtime story for a native-speaking child, the note in Turkish. Validated and retried exactly like the level.
- **Level.** `assessLanguageLevel(content, language)` returns `{ level, confidence, note }`: the CEFR level of the text as listening material for a learner of that language, the note in Turkish. The answer is validated against a JSON schema; an invalid answer is asked for once more, then `LlmOutputRejectedError`.
- **Translation.** `translateStory(story, targetLanguage)` returns `{ title, summary, content }`. The text goes to the model as an ordered paragraph list and comes back the same way. Before returning: typography is normalised to the content rules (no em dash, no emoji, no unicode ellipsis) and `checkTranslation()` rejects a wrong paragraph count (tolerance: one per ten paragraphs), a length ratio outside 0.4 to 2.5, the source handed back, untranslated paragraphs, an empty title or paragraph and an added translator note. A rejected translation is never saved. The model never writes a summary of its own (no source summary means null).
- **Background execution.** `src/modules/story-llm`: table `story_llm_tasks` (`StoryLlmTask`: type TRANSLATE | ASSESS_LEVEL | ASSESS_AGE_GROUP, status PENDING | RUNNING | DONE | FAILED, Turkish `error`, `resultStoryId`, `result` JSON, `force`, `attempts`, `model`) plus Bull queue `story-llm` (job `run-task`, one job per task row, 3 attempts, exponential backoff from 30 s). `StoryLlmTasksService` decides eligibility, creates and enqueues; `StoryLlmProcessor` runs one task at a time. Transient provider errors (429, 5xx, timeout, network) put the task back to PENDING and are retried; rejected model output, a provider 4xx and `StoryLlmTaskError` fail it at once. Every final write is conditional on the row still being RUNNING.
- **Stuck tasks.** A RUNNING task untouched for 30 minutes is marked FAILED the next time tasks are listed or a new one is requested; a PENDING task older than 2 minutes whose Bull job is gone is failed when the same work is requested again. Neither blocks a new task forever.
- **A finished translation** creates a new `Story`: DRAFT (a human reviews before publishing), `translationMethod` MACHINE, `textFidelity` TRANSLATED, `translatedFromId`, the source's `translationGroupId` (created on the source when it has none), a generated slug, its own copy of the cover object, and category, ageGroup, isPremium, default emotion/speed, credit and rights-basis columns copied. Not copied on purpose: `translatorName` (the source's human translator did not write this text), `rightsVerifiedAt/By` (a human verifies the new text), the pronunciation dictionary and the preprocessed segments. `originalTitle` / `originalLanguage` default to the source's title and language. With `replaceDraft` an existing sibling is overwritten in place only while it is still a DRAFT machine translation.
- **Level writes** go directly through Prisma (`languageLevelSource` AI, note with the confidence, assessed-at). A MANUAL level is never overwritten unless the task is forced; the write itself is conditional, so a level typed while the model was running survives.
- **Age group writes.** `Story.ageGroup` is required, so `ageGroupSource` (AI | MANUAL, null on rows older than the column) + `ageGroupNote` + `ageGroupAssessedAt` record who chose it. Same rules as the level: an age group sent to the admin create endpoint, or one that differs from the stored one on PATCH, is MANUAL; re-sending the stored value keeps the source; the source is never accepted from a request body; the AI write is conditional (source null or AI) unless the task is forced (409 `AGE_GROUP_IS_MANUAL` on request). A story created without an age group stores the placeholder THREE_TO_SIX with no source. `triggerAutoAssessAgeGroup` runs next to the level trigger on create (no age group chosen, `{ newStory: true }`) and on a text change, governed by `llm.autoAssessAgeGroup` (default true, env `LLM_AUTO_ASSESS_AGE_GROUP`). **On a text change it only re-assesses an age group the model owns**: source AI, or no source but an `ASSESS_AGE_GROUP` task already exists for the story (created without an age group, first assessment failed). A row with no source and no such task is a story from before the column, whose age group an editor chose: it is never replaced automatically, only by an explicit request from the panel. Do not loosen this: the panel re-sends the stored age group on every save, so the source of those rows stays null. A machine translation copies the age group and its source from the source story and is not assessed again; the seeder keeps an age group that has a source.
- **Automatic triggers** (`triggerAutoAssess`, `triggerAutoAssessMissing`): story created without a level, story text or language changed, after a translation, after `seed-stories` (every story without a level). Governed by the `llm.autoAssessLevel` setting (default true, env `LLM_AUTO_ASSESS_LEVEL`). They are called with `void`, catch everything and do nothing without a Gemini key, so they can neither fail nor slow the request. The CLI seeder (`prisma/seed-stories.ts`) has no queue and triggers nothing: use the batch endpoint afterwards.
- **Admin API** (`admin-content.controller.ts`; POSTs answer 202 and need SUPER_ADMIN or ADMIN): `POST /admin/stories/:id/translate`, `POST /admin/stories/translate-batch`, `POST /admin/stories/:id/level/assess`, `POST /admin/stories/level/assess-batch`, `POST /admin/stories/:id/age-group/assess`, `GET /admin/stories/llm-tasks` (declared before `stories/:id`). Coded errors: `TRANSLATE_SAME_LANGUAGE`, `TRANSLATION_EXISTS` (409, with `replaceable`), `LEVEL_IS_MANUAL` (409), `AGE_GROUP_IS_MANUAL` (409), `STORY_LLM_TASK_ACTIVE` (409), `STORY_EMPTY`, `STORY_NOT_FOUND`, `LLM_NOT_CONFIGURED` (503), `STORY_LLM_QUEUE_UNAVAILABLE` (503).
- **Live check without a server:** `npx ts-node -r tsconfig-paths/register scripts/story-llm-smoke.ts` translates the shortest seed story and assesses both texts (three Gemini calls, needs `GEMINI_API_KEY`).

### Bulk import, segments, narration cache, multi-part tales

Full write-up (Turkish, with costs): `docs/story-pipeline.md` at the workspace root. Migration `20261021120000_story_import_segments_parts`.

- **Bulk import** `POST /admin/stories/import` (SUPER_ADMIN, ADMIN; `AdminStoryImportService`, DTO `import-stories.dto.ts`): `{ stories: [...], dryRun? }`, at most 300 per request (the panel sends batches; JSON body limit 2 MB). Every story becomes a DRAFT with NO LLM and NO TTS call (no level / age assessment, no translation, no segmentation). Items are validated one by one with class-validator (a bad item is reported, the rest imported). Idempotent: `Story.importKey` = `<language>|<source url without trailing slash>|<title folded: NFKC, Turkish lower case, single spaces>` (unique), and an existing row with the same sourceUrl + language + title (case-insensitive) also counts: skipped, never updated. `pairKey` gives a deterministic `translationGroupId` (uuid v5), `partOf` + `partNumber` a deterministic `partGroupId` per language. Field mapping: contentWarnings (`ContentWarning` values) -> contentWarnings, author/collector/translator(+DeathYear) -> *Name columns, translationMethod (HUMAN | MACHINE; MACHINE = our AI translation, textFidelity then defaults to TRANSLATED and anything else is refused) and translatedFrom (tr | en, needs pairKey, another language: sets translatedFromId to the pair member of that language; when the source is imported later it adopts the waiting MACHINE sibling of its pair), collection -> sourceName, sourceEdition, licence -> licenseName, licenceUrl -> licenseUrl, attribution, licenceBasis -> rightsNote, description -> summary, level -> languageLevel (MANUAL), ageGroup (MANUAL), origin default PUBLIC_DOMAIN, textFidelity default VERBATIM, tags. None of the new columns (tags, sourceEdition, licenseName, attribution, importKey) reach the mobile API.
- **Segments** (`src/modules/story-segmentation`): `Story.preprocessedSegments` = `[{ text, emotion?, speed?, volume?, pauseAfterMs? }]` (Sonic 3 emotions, speed 0.6-1.5, volume 0.5-2, pause 0-3000 ms, at most 1500 chars / 4500 bytes per segment, 1000 segments). `segmentationVersion` is bumped on every write (import = 1, first narration, admin edit); `preprocessedModel` says who wrote them: `import`, `manual`, `fallback-split` or the Gemini model id. `Audio.segmentationVersion` records the version a narration was made from.
- **Lazy segmentation.** A story without segments is segmented on its first narration request: `AudioService.generateAudio` returns the Audio at once (GENERATING, 0 segments) and queues `prepare-audio` on `audio-generation`; `StorySegmentationService.ensureSegments` claims the story (`segmentationLockedUntil`, conditional on the version read, 3 min), calls Gemini (`preprocessStory`, emotion + speed tags) once, stores the result conditionally and releases. A concurrent request waits and reuses it. No Gemini key or a provider error: the deterministic splitter (`splitStoryForTts`, Turkish-aware sentence ends, never mid-sentence) is used for that narration only and NOT stored. Content drift: the split IS stored as `fallback-split`. Publishing does not segment (Gemini would be paid for stories nobody narrates).
- **Grouped synthesis** (`synthesis-plan.ts`, runtime setting `tts.groupSegments`, default true, env `TTS_GROUP_SEGMENTS`): Cartesia gets one request per run of segments with the same emotion and volume (Cartesia advises one emotion per generation; inline emotion tags are beta, English only), speed changes as inline `<speed ratio>` and pauses as `<break time>` (`cartesia-transcript.ts`), at most 1500 chars. Google Chirp 3 HD has no emotion: every segment shares requests up to 4500 bytes, pauses become `markup` pause tags (`[pause short]` < 400 ms, `[pause]` < 1000 ms, `[pause long]`), SSML `<break>` for non-Chirp voices; per-segment speed is not expressible (global speaking rate). One AudioSegment row and one `generate-segment` job per request (`job.parts` carries the segments). Off: one request per segment, as before. Billing is per character on both providers, so grouping changes requests and merge seams, not the price.
- **Admin editor**: `GET /admin/stories/:id/segments` (segments, version, source, vocabulary, cache summary), `PATCH /admin/stories/:id/segments` (`{ segments, expectedVersion? }`; 400 `SEGMENTS_INVALID`, 409 `SEGMENTS_VERSION_CONFLICT`; saves as `manual`, bumps the version and clears the narration cache), `segment-preview` (free split), `segments/llm-fill` (Gemini proposal, not stored), `DELETE .../segments` (next narration segments again).
- **Shared ready-made voice audio** (`shared-audio-key.ts`, `AudioService.generateSharedAudio`, migration `20261021180000_shared_preset_audio`, runtime setting `tts.sharePresetAudio`, default true, env `TTS_SHARE_PRESET_AUDIO`). A narration (`POST /narrations/:id/generate` passes `share: true`; `POST /audio/generate` never shares) of a story with a ready-made Google voice (provider GOOGLE, kind PRESET) uses ONE `Audio` row per `shareKey` = sha256 of { cache version, story id, `v<segmentationVersion>` or `lazy-v<n>` (no stored segments yet), sha256 of the text, synthesis voice id (`resolveSynthesisVoiceId`), story language, `tts.google.speakingRate`, pitch (non-Chirp only), `tts.groupSegments` }. Shared rows have `shared` true, no `userId` / `voiceProfileId` (DB CHECK `audio_owner_check`), `storyId`, `shareParams` and files under `shared-audio/<audioId>/`. `StoryNarration.audioId` is no longer unique. Flow: no row: create it and link the narration in one transaction (unique key: a simultaneous first request gets P2002 and attaches), then queue; READY: narration READY at once (socket `narration_status` only, no push, no TTS); PENDING / GENERATING: link, then re-read the audio (a completion in between is never missed); FAILED, or no progress for `SHARED_AUDIO_STALE_MS` (20 min): a conditional claim on status + updatedAt lets exactly one request regenerate (old segments and files dropped, FAILED narrations detached), the others attach. Completion and failure flip every not-yet-final narration of the audio with a conditional update each (one push per user). The quota unit is taken per user as before. `releaseAudio` (narration replaced or deleted) deletes owned audio and keeps shared audio (it is the cache; a shared audio with no narration stays until a cache clear). Stream and metadata of a shared audio need a narration of the caller pointing at it. `prepare-audio` for a lazy key moves the key to the stored version (P2002: keeps the lazy key) or drops it when the segments were not stored (free split after a Gemini error). Admin story delete removes the story's shared audios first. The admin audio list carries `shared` and `narrationCount`.
- **Narration cache** (`NarrationCacheService`): `GET|DELETE /admin/stories/:id/narration-cache`. Owned (cloned voice, or sharing off) audio per narration plus the story's shared audios, each counted once; the summary adds `sharedAudios`, `sharedNarrations`, `sharingEnabled`. Clearing runs `AudioService.adminDeleteAudio` for every distinct audio: GCS files + Audio/AudioSegment rows deleted, the narration turns FAILED with `NARRATION_AUDIO_REMOVED_MESSAGE`, gets `freeRegeneration` (the next generation takes no plan unit; carried over when POST /narrations replaces the FAILED row) and a socket `narration_status` FAILED (no push). The app streams (no offline copy), so a removed narration disappears from its library on refresh.
- **Shared covers** (`src/modules/stories/story-covers.ts`): covers carry no text, so one cover serves the whole tale. A story whose `coverImageUrl` is null shows (every story item: lists, search, detail, favourites, collections, `narration.story`) the cover of another language version (from the group member query of `loadStoryGroupInfo`, published, enabled languages), else of another part of its part group (one more query, only then); published before draft, then the first part. Items carry `coverKey` (sha256 of the translation group, else part group, else story id, 16 hex): the app's placeholder picture key, group ids stay private. Admin create / PATCH with a cover file and `applyCoverToTale: true` (the panel's "Bu kapağı tüm dillere ve bölümlere uygula", default on) writes the cover to every story reachable through translation and part groups (`loadTaleStoryIds`, at most 200). A cover object is deleted (replace, story delete) only when no other story still shows it.
- **Multi-part tales**: `partGroupId` + `partNumber` (unique together). `GET /stories/:id` adds `part: { number, total, next: { id, title, number } | null, previous: ... } | null` counting PUBLISHED parts only (`story-parts.ts`).
- **Related stories** `GET /stories/:id/related` (`StoriesService.getRelatedStories`, same 404 / 403 as the detail): `{ languages, parts, category }` of list-shaped items for the story page. `languages`: the other published versions of the tale in enabled languages, catalogue order. `parts`: the other published parts in part order, each with `partNumber`. `category`: up to `RELATED_CATEGORY_LIMIT` (12) published stories of the same category in the story's language, newest first, never a version or part of this tale, only part 1 of another multi-part tale, no premium stories for FREE. One `toItems` pass, so group info and favourites are read once.
- `npm run test:e2e` (`test/story-pipeline.e2e-spec.ts`) runs the import, the part links and two simultaneous first segmentations against the local Postgres and deletes its rows afterwards; `test/story-review.e2e-spec.ts` the review list, bulk publish (CC BY refusal), cover match and upload (stub storage) and bulk delete.

### Voice languages (clone language, contentLanguage, narration language mismatch)

- **Every voice has a language.** `VoiceProfile.language` stores a locale (`tr-TR`, `en-US`; clone rows from older app builds hold the bare `tr`). Every voice profile response (`toPublicVoiceProfile`, the status endpoint) adds the normalised `contentLanguage` (`tr`, `en`, ...), the same vocabulary as `story.language`, computed by `voiceContentLanguage()` in `src/common/utils/voice-language.ts`: a ready-made voice reads it from the voice id, a clone from the stored language (never from its opaque provider id), nothing known means Turkish. `GET /voice-profiles?language=tr,en` filters on it in memory. No column was added for this.
- **Clone languages.** `VOICE_LANGUAGES` in `src/common/constants/voice-languages.ts` (tr, en: code, locale, native name, Cartesia accent label). The texts of the clone flow per language live in `CLONE_LANGUAGE_CONTENT` (`clone-config.constants.ts`): reading script, script title, intro steps, tips, consent title, consent text, **its own consent version id** (`2026-10-v2` tr, `2026-10-en-v2` en; bump it with every change of the consent text, the upload is then refused with CONSENT_REQUIRED until the user consents to the new text) and the test sentence. The record is typed by the language list, so a new language without texts does not compile. Adding a language: one entry in `VOICE_LANGUAGES`, one in `CLONE_LANGUAGE_CONTENT`, legal review of the consent, then switch it on.
- **`tts.cloneLanguages` runtime setting** (env `VOICE_CLONE_LANGUAGES`, default `tr,en`) decides which of them are offered; read it only through `resolveCloneLanguages()` / `requireCloneLanguage()` (`voice-profiles/clone-languages.ts`). Empty or unknown falls back to Turkish. **The English consent text is an engineering translation and has not been through legal review** (see the TODO on `CLONE_CONSENT_TEXT_EN`); removing `en` from the setting switches English cloning off without a deploy.
- **`GET /voice-profiles/clone-config?language=en`**: optional, default Turkish (app builds in the field send nothing and get exactly the old texts). Returns `language`, `locale`, `supportedLanguages: [{ code, locale, nativeName, englishName }]` plus the texts in that language. Not an enabled voice language: coded 400 `VOICE_LANGUAGE_NOT_SUPPORTED` with `supportedLanguages`.
- **Create.** `POST /voice-profiles/v2` (and the legacy `POST /voice-profiles`) take `language` (`tr`, `en`, or a locale); the DTO validates it (`IsVoiceProfileLanguage`), the service stores the locale. A ready-made profile always stores the locale of its voice id. **Upload** checks `consentVersion` against the version of the profile's own language (400 `CONSENT_REQUIRED` carries the expected version and `language`).
- **Training.** `VoiceTrainingProcessor` sends Cartesia `language` (the profile language) and `accent` (`istanbul` for tr, `general-american` for en; Cartesia needs the label on the clone before accents can be added later). The accent is metadata: if Cartesia answers a 4xx that names the accent, `createVoiceClone` repeats the request once without it. The test sample and the default clone preview read `testSampleText` of the voice's language.
- **A voice of another language MAY narrate a story.** The old 400 `VOICE_LANGUAGE_MISMATCH` is gone. `describeNarrationLanguage()` puts `voiceLanguage`, `storyLanguage`, `languageMismatch` and `nativeVoiceUsed` on every narration response (create, list items, detail, per-story list, every answer of `POST /narrations/:id/generate`). The client shows "Dil tipleri uyuşmuyor. Aksan kaymaları olabilir." from them; to know beforehand it compares `voiceProfile.contentLanguage` with `story.language` itself (both are in the lists it already has).
- **Synthesis on a mismatch.** A Google voice id is bound to its locale, so `AudioGenerationProcessor` calls `resolveSynthesisVoiceId()`: a ready-made Chirp 3 HD voice reading a story of another language is synthesised with the voice of the SAME NAME in the story's locale (`tr-TR-Chirp3-HD-Achernar` on an English story becomes `en-US-Chirp3-HD-Achernar`, via `presetVoiceInLanguage()`); the profile row is never changed and `nativeVoiceUsed` is true. A story language without ready-made voices (Russian) falls back to the profile's own voice id (`nativeVoiceUsed` false). A cloned voice always keeps its id: the story language is sent to Cartesia as the request language and the result is accented.
- **Cartesia emotion.** Cartesia documents `generation_config.emotion` as beta and English only, yet `CartesiaTTSService.textToSpeech` sends an emotion on every request (default `neutral` from `tts.cartesia.defaultEmotion`). Left as it is on purpose: the Turkish output the owner approved was produced this way. Do not change it without listening tests.
- Presets exist per content language: a client lists the narrators of a language with `GET /voice-profiles/available-voices?language=<code>`.

### Ready-made voices (Google Chirp 3 HD only)

- **Static catalogue.** `src/common/constants/google-preset-voices.ts` holds the 30 Chirp 3 HD voice names with gender and the content language to locale map (tr tr-TR, en en-US, de de-DE, fr fr-FR, es es-ES, it it-IT, nl nl-NL, pt pt-BR, ar ar-XA). Russian is left out: Google serves only 8 of the 30 voices in ru-RU. A voice id is `<locale>-Chirp3-HD-<Name>`; the display name is the bare name ("Achernar"). Nothing calls Google `listVoices` any more: listing, creating a preset profile (`findPresetVoice`) and the preset preview all read the catalogue, so a Google outage cannot empty the list or reject a valid id. Standard and WaveNet voices are not offered; migration `20261014120000_chirp3_hd_preset_voices` moved existing preset profiles to Chirp 3 HD voices of the same gender and renamed auto-generated profile names.
- **`GET /voice-profiles/available-voices`.** Optional `language` (content language code, or several separated by commas; default `content.defaultLanguage`) and `provider`. Without `provider`: `{ google: Voice[], cartesia: [] }` (the shape app builds in the field parse); with it: `{ provider, voices }`. Voice: `id`, `name`, `language` (English name), `languageCode` (locale), `contentLanguage` (matches `story.language`), `gender`, `description`, `provider`, `isPremium` (always false). A language without ready-made voices returns none. The list is not filtered by `content.enabledLanguages`.
- **Free for everyone.** `isPremiumVoice` (`src/common/utils/voice-tier.ts`) is kind-based: only cloned voices are premium. A narration with a ready-made voice counts against `PLAN_LIMITS.*.presetNarrations`, a cloned voice against `cloneNarrations` (see "Plans, limits and in-app purchases"). Plan copy and the quota message say "hazır anlatıcı sesler" and "kendi sesin", never "premium sesler".
- **Synthesis request.** Built in one place, `buildGoogleSynthesisRequest` (`tts-providers/ssml.helper.ts`). A Chirp voice gets plain text and `audioConfig.speakingRate` (clamped to 0.25..2) and **never `pitch`**: Google answers `INVALID_ARGUMENT: This voice does not support pitch parameters` when the key is present, which failed every Chirp synthesis in production. Any other Google voice gets the SSML envelope (paragraphs and pauses only, no `<prosody>`) and rate plus pitch once through `audioConfig`.
- **Preview cache.** Key `voice-previews/GOOGLE/<PRESET_PREVIEW_CACHE_VERSION>/<locale>/<voiceId>/<prosody hash>[-<text hash>].mp3`. Bump the version constant in `voice-profiles.service.ts` whenever the way a preset is synthesized changes; old objects stay in storage and are never read. The default preview line is in the language of the voice (`PRESET_PREVIEW_TEXTS`).

### Plans, limits and in-app purchases

**Plans** (`SubscriptionPlan`): FREE, MINI, PRO (sold and shown as "Premium"; the value stays PRO because app builds in the field parse it) and CREATOR (admin grant only, never sold, not in the public plan list). Every number lives in `PLAN_LIMITS` (`src/common/constants/plans.constants.ts`); slots, the plan list, GET /usage and the limits engine read it.

| | FREE | MINI (49,99 TL / month) | PREMIUM = PRO (199,99 TL / month, 1.499,99 TL / year) | CREATOR (grant) |
|---|---|---|---|---|
| Ready-made voice narrations | 20 a month | unlimited | unlimited | unlimited |
| Cloned-voice narrations | 1 in total (lifetime) | 5 a month | 20 a month | 20 a month |
| Clone creations | 1 in total (lifetime) | 2 a month | 5 a month | 10 a month |
| Clone voices held at once | 1 | 1 | 3 | 5 |
| Ready-made voices held at once | 3 | 10 | 10 | 20 |
| Background / lock-screen playback, premium stories | no | yes | yes | yes |

- **Counting is append-only.** Monthly counters on `usage_limits` (calendar month, server-local time; renews on the 1st), lifetime counters on `usage_lifetime` (never reset). Every cloned-voice narration and every clone creation counts on the lifetime row on any plan, so a lapsed paid user has no free one left. A narration takes its unit atomically when generation starts (`UsageService.consumeNarration`, a conditional update, so concurrent requests cannot overshoot); it is given back only when the generation could not even start. `POST /audio/generate` counts the same way.
- **Clone creations count creations, not clone rows.** Deleting a clone frees a slot but never a creation, so delete-and-record-again cannot pass the plan. The creation is taken when the upload is accepted (`tryConsumeCloneCreation`) and the time is stored on `voice_profiles.creationChargedAt`. The only refund (`refundCloneCreationForProfile`, once per profile, to the month it was taken in) is a training that ended FAILED with no voice made: our rejection of the clip, a Cartesia rejection, retries used up, the 20 min timeout sweeper, or a queue failure at upload. A READY clone is never refunded.
- **Coded 403s** (localized `message`, see "UI language for server text", says what renews when): `QUOTA_PRESET_MONTHLY`, `QUOTA_CLONE_LIFETIME`, `QUOTA_CLONE_MONTHLY` (body: `code, bucket, tier, plan, limit, used, period, renewsAt`), `CLONE_CREATION_LIMIT` (`code, plan, limit, used, period, renewsAt`), `CLONE_SLOT_LIMIT`, `PRESET_SLOT_LIMIT` (unchanged). The old `NARRATION_QUOTA_EXCEEDED` and `CLONE_MONTHLY_LIMIT` codes are gone; GET /voice-profiles/slots keeps `clone.monthlyCreated / monthlyLimit` for old builds (lifetime numbers on FREE) and adds `clone.creations { used, limit, period, renewsAt, canCreate }`.
- **GET /usage**: `{ plan, planName, renewsAt, buckets: { presetNarrations, cloneNarrations, cloneCreations }: { limit (null = unlimited), used, remaining, period: month | lifetime, renewsAt (null for lifetime) }, voiceSlots: { preset, clone }: { used, limit }, features: { backgroundPlayback, premiumStories } }`. `/usage/current`, `/usage/limits` and `/subscriptions/usage` keep their old shapes (-1 = unlimited).

**Entitlement and precedence.** `resolveEffectivePlan` (`src/common/utils/subscription-plan.ts`) takes the better (`PLAN_RANK`) of the store-backed columns (`plan / status / currentPeriodEnd`, 24 h renewal grace on store rows) and the admin grant (`grantPlan / grantEndsAt`, null end = open). Store code never writes the grant columns and admin code writes only them, then both call `recomputeSubscription` (`subscriptions/store/entitlement.ts`), which derives the row from the best entitling purchase (ACTIVE, CANCELED or GRACE until `expiresAt`), else mirrors a running grant, else records the latest purchase as EXPIRED. So a store write can never shorten a grant and an ended grant never hides a store subscription. Admin deactivation ends the grant too.

**Store product map** (`src/common/constants/store-products.constants.ts`, the only place ids live): Google Play `mini_monthly` (MINI), `pro_monthly` and `pro_yearly` (PRO); App Store `io.sesly.mini_monthly`, `io.sesly.pro_monthly`, `io.sesly.pro_yearly`. An unknown product is 400 `PRODUCT_UNKNOWN` before any write (in a notification: recorded and ignored). No `premium_*` or `creator_*` product exists.

**Client contract** (the app buys with `obfuscatedAccountId` (Android) / `appAccountToken` (iOS) = the Sesly user id, then calls the backend and finishes the store transaction only after a 200 or a 4xx; on 503 it keeps the transaction and retries later):
- `POST /subscriptions/google/validate { purchaseToken, productId?, packageName? }` and `POST /subscriptions/apple/validate { signedTransaction }` (StoreKit 2 JWS; the old `receiptData` / verifyReceipt path is removed, no build ever called it). 200: `{ success, entitled, purchase: { platform, productId, plan, billingPeriod: month | year, state, expiresAt, autoRenew }, subscription: <GET /subscriptions/current>, expiresAt, isActive }`. Errors: 400 `RECEIPT_INVALID` (bad signature, other app / package, token Google does not know), 400 `PRODUCT_UNKNOWN`, 409 `RECEIPT_IN_USE` (bound to another account, or bought for another account id), 503 `STORE_UNAVAILABLE` / `STORE_NOT_CONFIGURED` (`retryable: true`).
- `GET /subscriptions/current`: always 200 (no row = FREE): `{ plan (effective), planName, isPaid, status, source: APPLE | GOOGLE | ADMIN | STRIPE | null, currentPeriodEnd, cancelAtPeriodEnd, willRenew, inGracePeriod, productId, billingPeriod, managementUrl, grantedPlan, storePurchase }`. Never a store token or transaction id.
- `GET /subscriptions/plans` (public): FREE, MINI, PRO with `name, price, yearlyPrice, currency, appleProductId / googleProductId` (monthly, the names old builds read), `appleYearlyProductId / googleYearlyProductId`, `products[] { platform, productId, billingPeriod, referencePrice }`, `features[]`, `allowances` and the legacy `limits`. Prices are reference list prices; the app shows the store price.

**Google Play.** `GooglePlayClient` (service account, scope androidpublisher): `purchases.subscriptionsv2.get` for the configured package only, `purchases.subscriptions:acknowledge` when the acknowledgement is pending (an unacknowledged purchase is refunded after three days; a failed ack is retried on the next message). States: ACTIVE, IN_GRACE_PERIOD, CANCELED grant until `expiryTime`; ON_HOLD, PAUSED, EXPIRED, PENDING do not. `linkedPurchaseToken` marks the old purchase REPLACED. The obfuscated account id must be the caller. RTDN: `POST /webhooks/google-play` (Pub/Sub push) verifies the OIDC token (signature, audience `GOOGLE_PLAY_PUBSUB_AUDIENCE`, email `GOOGLE_PLAY_PUBSUB_SERVICE_ACCOUNT`, email_verified; 401 otherwise, 503 when unset), is idempotent on the Pub/Sub message id, re-fetches subscriptionsv2 for the token and updates the row; a voided purchase is REVOKED. A purchase seen first by notification is bound through the obfuscated account id.

**Apple.** `AppStoreClient` verifies with `@apple/app-store-server-library` `SignedDataVerifier` (online checks on) against the root certificates in `APPLE_ROOT_CERTS_DIR` (default `assets/apple-root-certs/`), bundle id and environment (Production first, Sandbox accepted unless `APPLE_ALLOW_SANDBOX=false`; Production needs `APPLE_APP_APPLE_ID`). Validation checks product, `appAccountToken`, expiry and revocation; with the optional App Store Server API key it re-reads the latest status. A restore never pulls back a later expiry. `POST /webhooks/apple { signedPayload }` (Notifications V2) verifies, is idempotent on `notificationUUID`, ignores an older `signedDate` than the stored state, and maps SUBSCRIBED / DID_RENEW / DID_CHANGE_RENEWAL_STATUS / DID_CHANGE_RENEWAL_PREF / OFFER_REDEEMED / RENEWAL_EXTENDED / REFUND_REVERSED from the signed transaction and renewal info, DID_FAIL_TO_RENEW to GRACE (subtype GRACE_PERIOD, until gracePeriodExpiresDate) or ON_HOLD, EXPIRED / GRACE_PERIOD_EXPIRED to EXPIRED, REFUND / REVOKE to REVOKED. A purchase seen first by notification is bound through `appAccountToken`.

**Webhook answers.** 200 for processed, replayed (`status: duplicate`) and deliberately ignored messages (test, other package, unknown product, no account yet); 400/401 for data that does not verify; 500 when processing failed (the store redelivers; the event row is FAILED and a redelivery is processed again).

**Tables.** `store_purchases` (one row per Apple original transaction / Google token, unique per platform: the account binding), `store_events` (every validation and notification, unique `platform + externalId`), `usage_lifetime`, plus `subscriptions.grantPlan / grantEndsAt / storePurchaseId` and `voice_profiles.creationChargedAt`. Migration `20261016120000_plans_limits_store_purchases` is additive; it copies existing admin grants into the grant columns and fills `usage_lifetime` from the history (summed monthly counters or existing rows, whichever is larger), so nobody gets a fresh FREE allowance from the deploy.

**Not handled on purpose.** Account deletion cannot cancel a store subscription (only the user can, in the store); it is logged. A user who deletes the account and signs up again gets a new FREE allowance. A narration whose generation fails after it started is not refunded.

### Legal documents (per language)

- **One row per (slug, language).** `LegalDocument` (unique `slug + language`) and `LegalDocumentVersion` (slug and language denormalised, index `slug, language, version`) in `src/modules/legal-documents`. Languages: `LEGAL_DOCUMENT_LANGUAGES` in `legal-languages.ts` (`tr`, `en`); rows from before migration `20261019120000_legal_documents_language` are `tr`. Version numbers count per document, so the English ToS has its own v1. Turkish is the canonical text.
- **Public** (`@Public`, also allowed during maintenance): `GET /legal?language=` and `GET /legal/:slug?language=`. `language` is optional (`tr` | `en`, case and a region suffix ignored, absent = `tr`, anything else or an unknown query parameter = 400). A language without a published version gets the published Turkish snapshot; `language` in the response (`{ slug, language, title, contentMd, version, publishedAt }`) is the language actually served, otherwise the shape is unchanged. A draft is never served (reads go to the version table only). 404 only when neither language is published. The list returns one entry per slug.
- **Admin** (`admin-content.controller.ts`; writes SUPER_ADMIN, ADMIN): every per-document route takes `?language=tr|en` (absent = `tr`, so the panel's old calls address the Turkish documents unchanged): `GET /admin/legal/:slug`, `GET /admin/legal/:slug/versions`, `PATCH /admin/legal/:slug` (body `title?`, `contentMd?`; `slug` or `language` in the body is 400), `POST /admin/legal/:slug/publish` (snapshots and publishes only that language). `GET /admin/legal?language=tr|en|all` (absent = `tr`; `all` = every language, slug asc, Turkish first). `POST /admin/legal` body `{ slug, language?, title, contentMd }` creates a DRAFT; 409 when that (slug, language) exists. Admin and version rows carry `language`; 404 messages name the language (`Legal document "tos" (en) not found`).
- **Texts.** Every legal text, Turkish included, lives only in `src/modules/legal-documents/content/<slug>.<language>.md` (slugs `CANONICAL_LEGAL_SLUGS`: tos, privacy, data-deletion). Body only: an optional first line `# Title` becomes the title, else `DEFAULT_LEGAL_TITLES` (Kullanım Şartları, Gizlilik Politikası, Veri Silme; Terms of Use, Privacy Policy, Data Deletion). No date line. `nest-cli.json` copies `content/*.md` to `dist`; `legal-content.loader.ts` also looks under `src/` from the working directory. The loader spec requires one file per slug and language and checks every one against the text rules (no em dash, ellipsis, arrows, bullets, emoji; no Stripe; no destek@sesly.app; info@sesly.io present). To change a text: edit the file, then publish it (panel or the script below).
- **Seeder** (`legal-documents.seeder.ts`, on boot, fail-soft per document, never overwrites a row in any language): a missing Turkish document is created from `content/<slug>.tr.md` and published as v1 (a missing Turkish file is logged as an error and that document is skipped). A missing English document is created as a DRAFT (v0, no version row) only when `content/<slug>.en.md` exists, and is never published by code: an editor reviews and publishes it in the panel.
- **Republish** (`scripts/republish-legal.ts`, logic in `legal-republish.ts`; Turkish only): compares the published Turkish version of each slug with `content/<slug>.tr.md` (line endings and surrounding whitespace ignored) and publishes the file as the next version where it differs; a missing document is created as v1. All files are read before the database is touched. `--dry-run` reports and writes nothing (run it first); an unknown argument stops the script. It replaces a Turkish text published from the panel that differs from the file, so copy panel edits into the file first.

### Service emails (Resend, per language)

- **Kinds**: `welcome` (first sign in, fail-soft) and `password_reset`, each in every UI language (`EMAIL_TEMPLATE_LANGUAGES` = `UI_LANGUAGES`, tr and en). Sent through Resend (`RESEND_API_KEY`, `EMAIL_FROM`; without a key nothing is sent). Logs name an address only by `emailLogRef` (sha256 prefix). The old email-change verification and token reset paths are gone (migration `20261105090000_email_templates` also drops their `users` columns); `PATCH /users/me` no longer accepts `email`.
- **Texts vs layout**: `src/modules/email/templates/`. Text fields per template: `subject`, `preheader`, `heading`, `body`, `buttonLabel`, `note`, `footer` (`EMAIL_FIELD_SPECS`: limits, one line or not, allowed placeholders `{{name}}` / `{{email}}` / `{{link}}`). Body, note and footer: paragraphs on an empty line, `**bold**`; without a name `{{name}}` goes with the space before it. Code defaults in `email-template.defaults.ts`; a row in `email_templates` (unique kind + language) overrides them, a database error falls back to the default. The HTML (`email-layout.ts`) is code: the "murekkep" dark design of sesly-frontend, table based, inline styles + bgcolor, plain-text alternative; every text and value is escaped. `validateEmailTemplateFields` (required fields, limits, placeholders, UI text rules via `common/utils/ui-text-rules.ts`) guards panel saves; the defaults pass it in the spec.
- **Language**: welcome = Accept-Language of the first sign in, else tr. Password reset = body `lang`, else Accept-Language, else `UserPreferences.uiLanguage`, else tr.
- **Password reset**: public `POST /auth/password-reset` `{ email, lang? }` (`PasswordResetService`). Always 202 `{ accepted: true }` for a valid address; the lookup, `admin.auth().generatePasswordResetLink` and the send run after the answer, so neither body nor timing tells whether an account exists. 429 `RATE_LIMITED`: 10 per hour per IP (route `@Throttle`), 3 per hour per address (same ThrottlerStorage, hashed key). The email links to `<FRONTEND_URL>/auth/action?mode=resetPassword&oobCode=..&apiKey=..&lang=..` (sesly-frontend `pages/AuthAction.tsx`), the code taken from Firebase's link. The app no longer calls Firebase's `sendPasswordResetEmail`.
- **Admin** (`admin-ops.controller.ts`): `GET /admin/email-templates` (kinds, languages, field specs, placeholders, every template with `fields`, `defaults`, `source`), `GET /admin/email-templates/:kind/:language`, `POST .../preview` (body = optional draft fields; `{ subject, html, text, problems[] }`, sample values) for SUPER_ADMIN and ADMIN; `PUT .../:kind/:language` (whole text; 400 `EMAIL_TEMPLATE_INVALID` with `problems[]`), `DELETE` (back to default), `POST .../test` `{ to, ...draft }` (`[Test]` subject, sample link; 503 without Resend) for SUPER_ADMIN only. Audit lines `AUDIT email template saved|reset`.

## Internationalization

Uses `nestjs-i18n` with JSON translation files in `src/i18n/{en,tr}/` (`errors`, `messages`, `notifications`, `common`). `HttpExceptionFilter` translates error messages based on request locale.

### UI language for server text (Turkish + English)

The app sends its UI language as `Accept-Language` (`tr` | `en`) on every request. Server-written user-facing text is never a hardcoded Turkish string any more; it is an i18n key with a Turkish and an English text (`src/common/i18n/`).

- **Errors**: throw with the KEY as `message` (`new NotFoundException('errors.stories.notFound')`, or spread `localizedError(key, args)` into a coded body next to `code`). The filter translates only key-shaped messages, per Accept-Language (none: `i18n.defaultLocale`). `messageArgs` fills `{name}` placeholders: a `Date` is written per language (`formatUiDate`: "1 Kasım" / "November 1"), a `{ tr, en }` value (`localizedLanguageName`, `serverTextInAllLanguages` for optional sentences) picks its language; `messageArgs` is never sent. Codes and every other body field stay as they were (clients branch on codes). Validation messages in DTOs are keys too; texts that list valid values are checked against the constants by `server-text.spec.ts`.
- **Text the server writes on its own** (in-app notification row, socket payload, FCM push, failure messages stored on a row: `StoryNarration.errorMessage`, `VoiceProfile.errorReason`): `serverText(key, language, args)` with the owner's stored language, `resolveUserUiLanguage` / `resolveUserUiLanguages` (`user-ui-language.ts`): `UserPreferences.uiLanguage`, else `tr`; never throws. Never store a key on a row.
- **Stored language**: nullable `UserPreferences.uiLanguage` (migration `20261104090000_user_preferences_ui_language`). `PATCH /users/me/preferences { uiLanguage: 'tr' | 'en' | null }` (case and region suffix ignored, null clears, anything else 400 `errors.validation.uiLanguage`); GET and PATCH return `uiLanguage` (null when never set). Also recorded from Accept-Language (tr / en only, other languages leave it alone, fail-soft) at `POST /auth/firebase/verify` and `POST /auth/refresh`, so app builds that never send the field get it too.
- `GET /app/config` `updateMessage`: English for Accept-Language en (`APP_UPDATE_MESSAGE_EN` overrides), else Turkish (`APP_UPDATE_MESSAGE`); `Vary: Accept-Language`.
- Specs: `renderMessage(errorOrBody, lang)` and `createI18nStub()` in `src/test-utils/i18n.ts` render keys from the real files.
- **Left Turkish on purpose**: admin panel copy (`/admin` routes, publish rules, collections admin, settings registry, story labels), plan `features` / `PLAN_NAMES` in `/subscriptions/plans` and `planName` (the app uses its own plan copy), ready-made voice `description` and content warning labels (the app shows its own copy). Emails are per language, see "Service emails".
